# Feature Specification: chart-eval-suite（html-visualization 评测集）

**Created**: 2026-11-08  
**Status**: Draft  
**Input**: User description: "增加这个skill的评测集，生成针对14种图的场景对应数据，并根据数据触发skill，生成对应的图片，并对生成效果进行评分，我可以辅助进行二次评价修正结果"

## Overview

为 html-visualization skill 建立一套可复现的评测基准：14 种图型各配 1 个真实业务基准场景（14 例内差异化覆盖 4 套主题与多类长宽比），由 Agent 按 SKILL.md 工作流逐场景生成 HTML→PNG，再按「硬指标核验 + AI 视觉评分 + 用户复评表」三层方案对生成效果评分；用户基于复评表对不满意的图进行二次评价，驱动修正与重渲染，最终沉淀为 skill 仓库内的 `eval/` 评测资产。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 评测数据集：14 种图型的基准场景 (Priority: P1)

为每种图型编写 1 个贴近真实业务的基准场景用例（如折线=月度活跃用户趋势、甘特=项目排期、漏斗=转化漏斗），包含业务标题、副标题、真实感数据、指定主题与长宽比，形成结构化评测数据集。14 例的主题与长宽比差异化分配：4 套主题（light/business/dark/warm）每套至少被 2 例覆盖，长宽比至少覆盖 16:9、1:1、9:16 三类。

**Why this priority**: 评测数据集是整个评测的输入基础，没有它后续生成、评分都无法进行。

**Independent Test**: 检查评测数据集文件中 14 个用例字段完整、图型无遗漏、主题/比例覆盖达标。

**Acceptance Scenarios**:

1. **Given** 14 种图型清单，**When** 编写评测数据集，**Then** 每种图型恰好有 1 个基准场景用例，字段完整（场景 ID、图型、标题/副标题、数据、主题、长宽比、评分要点）
2. **Given** 4 套主题与常用长宽比，**When** 分配用例参数，**Then** light/business/dark/warm 每套至少 2 例覆盖，16:9、1:1、9:16 至少各 1 例覆盖
3. **Given** 任意用例，**When** 阅读其数据，**Then** 数据与场景语义自洽（字段、量纲、类别数符合该图型的判定规则）

---

### User Story 2 - 逐场景触发 skill 生成图片 (Priority: P1)

Agent 严格按 SKILL.md 六步工作流（解析数据特征 → 确认喜好与输出参数 → 选型选主题 → 生成 HTML → 渲染 PNG → 视觉自检）逐场景真实执行，每例产出可复用的 `.html` 与精确比例的 `.png`。

**Why this priority**: 这是评测的核心动作——用真实使用方式检验 skill 工作流与产物质量。

**Independent Test**: 逐场景执行后检查 `eval/` 下产物齐全且可独立打开/渲染。

**Acceptance Scenarios**:

1. **Given** 评测数据集中某用例，**When** 按 SKILL.md 工作流执行，**Then** 产出对应 `.html` 与 `.png`，且主题、长宽比与用例指定一致
2. **Given** 全部 14 例执行完毕，**When** 汇总产物，**Then** 14 套 HTML+PNG 齐全，无遗漏
3. **Given** 渲染脚本输出，**When** 核对结果，**Then** `ok: true` 且 `pixels` 与目标比例一致

---

### User Story 3 - 硬指标核验 (Priority: P2)

对每张产物 PNG 自动核验客观硬指标：渲染成功（非空白）、像素尺寸与目标比例精确一致、产物文件完整可打开。硬指标不通过的图必须修复重渲染。

**Why this priority**: 硬指标是评分的地基，失败的产物没有视觉评分的意义。

**Independent Test**: 对每张 PNG 核验像素尺寸与渲染结果，输出逐例通过/失败清单。

**Acceptance Scenarios**:

1. **Given** 某例渲染输出 JSON，**When** 核验，**Then** `ok: true` 且像素比例与用例指定一致
2. **Given** 某例硬指标失败，**When** 定位原因，**Then** 修正 HTML 后重渲染直至通过

---

### User Story 4 - AI 视觉评分 (Priority: P2)

对每张通过硬指标的 PNG 进行视觉检查并评分（0-10）：可读性（无文字溢出/裁切/重叠、中文渲染正常）、布局（比例协调、留白合理、元素对齐）、主题一致性（配色符合指定主题令牌）、数据表达（图型选择合理、数据可读、符合设计规范）。评分附问题清单。

**Why this priority**: 视觉评分直接回答「生成效果好不好」，是评测的核心产出。

**Independent Test**: 每张图有评分记录（分数 + 问题清单），可对照图片复核。

**Acceptance Scenarios**:

1. **Given** 某例 PNG，**When** 视觉检查，**Then** 输出 0-10 分与具体问题清单
2. **Given** 发现文字溢出/空白/方块字等问题，**When** 问题影响可读性，**Then** 修复后重渲染并更新评分

---

### User Story 5 - 用户复评表与二次修正 (Priority: P3)

生成一份复评表（markdown）：逐例列出硬指标结果、AI 视觉评分与缩略图引用，预留用户复评列。用户对不满意的图标记异议与批注，Agent 据此修正 HTML、重渲染并更新评分，直到用户确认。

**Why this priority**: 用户辅助二次评价是本次评测的质量闭环，但依赖前四个故事的产物。

**Independent Test**: 复评表交付给用户填写，异议图修正后重渲染并更新记录。

**Acceptance Scenarios**:

1. **Given** 全部 14 例完成硬指标与视觉评分，**When** 生线复评表，**Then** 表内含每例的分数、问题清单与图片引用，预留「用户复评」列
2. **Given** 用户在复评表中标出异议图，**When** Agent 处理，**Then** 异议图被修正、重渲染、评分更新
3. **Given** 用户确认全部通过，**When** 收尾，**Then** 评测报告定稿并归档到 `eval/`

### Edge Cases

- 某图例渲染失败（浏览器缺失、CDN 失败且本地兜底路径错）时：按 SKILL.md 常见错误速查修复后重试，仍失败则在评分报告中记录失败原因，不阻塞其他图例
- 评测数据中类别过多/系列过多导致标签重叠：按设计规范处理（排序、合并「其他」、缩小字号），并在问题清单中记录
- 用户复评引入对评测数据本身的修改（换数据/换主题）：视同用例参数变更，同步更新评测数据集与复评表

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 评测数据集 MUST 覆盖全部 14 种图型（折线、堆叠折线、柱状、横向条形、堆叠柱状、饼图、环形、散点、分布散点、线性回归、雷达、漏斗、仪表盘、甘特图），每种至少 1 个基准场景
- **FR-002**: 14 例的主题分配 MUST 覆盖全部 4 套主题且每套至少 2 例；长宽比 MUST 至少覆盖 16:9、1:1、9:16 三类
- **FR-003**: 每个用例 MUST 包含：场景 ID、目标图型、业务标题与副标题、场景数据、主题、长宽比、评分要点；数据为标注虚构的真实感业务数据
- **FR-004**: 每个场景 MUST 按 SKILL.md 六步工作流执行，产出 `.html` 与 `.png` 双产物
- **FR-005**: 每张 PNG MUST 通过硬指标：渲染成功且像素尺寸与用例指定比例精确一致
- **FR-006**: 每张 PNG MUST 有 0-10 分的视觉评分与具体问题清单
- **FR-007**: 系统 MUST 生成复评表供用户二次评价；用户标记异议的图 MUST 被修正并重渲染，评分同步更新
- **FR-008**: 评测数据、生成产物、评分报告 MUST 归档在仓库 `eval/` 目录下，结构清晰、可复现再执行

### Key Entities *(include if feature involves data)*

- **EvalCase（评测用例）**: 场景 ID、目标图型、业务标题/副标题、场景数据、主题、长宽比、评分要点；是生成与评分的输入
- **ScoreRecord（评分记录）**: 关联场景 ID、硬指标结果（渲染状态/像素尺寸）、视觉评分（0-10）、问题清单、用户复评结论、修正轮次；汇总为评分报告

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 14/14 场景全部产出 HTML+PNG，硬指标通过率 100%（修复后）
- **SC-002**: 4 套主题每套 ≥2 例覆盖；16:9、1:1、9:16 三类长宽比各 ≥1 例覆盖
- **SC-003**: 每张图均有 0-10 视觉评分与问题清单，评分记录可对照图片复核
- **SC-004**: 复评表交付用户；用户标记异议的图 100% 完成修正重渲染与评分更新

## Assumptions

- 评测数据为构造的真实感业务数据（在用例中标注虚构），用于检验渲染与工作流，不代表真实统计
- 本机具备 skill 运行环境：Python 3.8+、Pillow、Chrome/Edge 之一
- AI 视觉评分由当前会话完成（打开 PNG 逐项检查）；用户是最终质量仲裁者
- 本次不编写自动化 eval runner 脚本（Agent 逐场景执行）；runner 留作后续迭代

## Open Questions

- 用户复评的载体确认为 markdown 复评表（已确认默认方案，无遗留问题）
- 评测集是否随 skill zip 打包分发：本次不打包，仅作为仓库内评测资产（如需分发可在 build-skill-zip.py 中扩展）
